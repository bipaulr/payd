# P11. README and submission text

Read CLAUDE.md and the codebase. Write the submission documents from what
the code actually does. Do not describe features that are not built.

README.md:
- One-line pitch, hosted demo URL (APP_URL), video link placeholder.
- The problem and who it is for, in five sentences.
- A 60-second "try it" path for judges.
- How PayPal is used: each API, where in the code, and why.
- How AI is used: each model or tool, where in the code, and why.
- Architecture diagram in Mermaid.
- Setup from a clean clone: prerequisites, env vars, sandbox accounts,
  migrate, seed, run, tests.
- Sponsor tools used: AG Grid, Render.
- Limitations and what comes next.

docs/DEVPOST.md:
- Project description with these headings: Inspiration, What it does, How we
  built it, Challenges, What we learned, What's next.
- A "Tools" section naming every model and AI service and how it was used.
  Include Claude Code as the coding tool.
- Write it so each of the five judging criteria is answered somewhere:
  technological implementation, design, potential impact, innovation,
  presentation.

Plain language. Short sentences. No hype words. No em dashes.

Final check: README.md and docs/DEVPOST.md exist, every command in the
README runs, and no feature is described that the code does not have.
