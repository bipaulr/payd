# P3. Bill extraction

Read CLAUDE.md and docs/PLAN.md. Build the extraction milestone.

- POST /api/bills accepts one image or PDF up to 5 MB. Store the bytes and a
  SHA-256 hash in Postgres. If the hash exists, return the existing bill.
- extractBill(file) in lib/extract calls the vision model and returns a
  Zod-validated object: vendor name, vendor PayPal email if printed, invoice
  number, issue date, due date, currency, line items, subtotal, tax, total,
  payment instructions text, and a 0 to 1 confidence for each field.
- Keep the model provider behind one small interface so it can be swapped.
  Default to Google Gemini using GEMINI_API_KEY and VISION_MODEL from .env (free tier). Check the current Gemini model id and its image and PDF input support in the docs. Respect free-tier rate limits: retry on 429 with backoff.
  Read the provider's current docs for structured output and PDF input.
- On validation failure, retry once with the error message, then mark the
  bill needs_review with the raw output saved.
- Match the bill to a Vendor by normalised name and email. If there is no
  match, attach a proposed new vendor. Never auto-create a vendor silently.
- Any field under 0.7 confidence is flagged for review.
- scripts/eval-extract.ts runs every file in samples/ against its expected
  JSON and prints per-field accuracy.
- If samples/ is empty, create three simple test bills as PDFs with invented
  vendors first, plus their expected JSON.

Final check: typecheck, lint and tests exit 0, and the eval script runs on
at least three sample bills. Report the per-field accuracy.
