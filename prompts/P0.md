# P0. Plan

Read CLAUDE.md. Write docs/PLAN.md and no app code.

The product: a shop owner uploads bills (photo or PDF). payD extracts the
fields with a vision model, runs six risk checks (duplicate, payee changed,
amount anomaly, math mismatch, lookalike vendor, pressure language), and
queues each bill for approval. Approved bills are paid with PayPal Payouts.
A PayPal webhook marks them paid. Everything appears in an AG Grid ledger.
A demo mode loads sample data with one click. Stretch goal: an agent command
bar that creates and sends PayPal invoices using the PayPal Agent Toolkit.

The plan must cover:
1. Data model: Vendor, Bill, BillLineItem, RiskFlag, Approval, Payout,
   WebhookEvent, Invoice, ActivityLog.
2. Bill state machine: uploaded, extracted, needs_review, approved, paying,
   paid, failed, rejected. List the allowed transitions.
3. Pages and API routes.
4. Every PayPal call we need, each with a link to the doc page you actually
   opened: OAuth token, Payouts batch create and get, webhook signature
   verification, the payout webhook event names, and the Agent Toolkit
   invoice tools for the Vercel AI SDK.
5. Anything that will not work in PayPal sandbox, with a fallback.
6. A build order in these milestones: scaffold, PayPal core, extraction,
   risk engine, review and pay screens, ledger, agent, demo mode, polish.

Keep it under 300 lines. Record open choices in docs/DECISIONS.md.

Final check: docs/PLAN.md exists, covers all six points, and every PayPal
doc link in it returns a real page.
